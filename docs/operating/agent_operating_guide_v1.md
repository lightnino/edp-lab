# Agent Operating Guide V1 — Shared Operational Procedures

**Status:** Prospective procedural companion to the [binding cross-lifecycle Operating Contract](../workflows/agent_operating_contract_v1.md). Covers Acquisition/Universe, Cohort/Model, and Validation/Freeze. This Guide grants no permissions, deploys no credentials and does not replace the independently installed protected 0A policy. For historical execution detail consult the original signed receipts/incidents, not this reusable Guide.

## Before starting a run

1. Identify the **actual** Lifecycle and actor: Acquisition RAW-write, Universe approval/readback, Cohort RAW-read and CLEAN/QUERYABLE write, or Validation/Freeze. Verify the owner's approved Universe/policy or applicable standing approval, exact source/RAW hashes/locators and prior accepted result freeze.
2. Inspect Git/main, approved contract/model/parser/registry pins, held-out membership, prior signed checkpoint and run destination. Check installed protected 0A policy/issuer/verifier **operational status**; proposed files or local green tests do not qualify.
3. Obtain an exact short-lived grant from the separately protected broker under installed standing policy. Never make an agent-edited repository file, untrusted local manifest or copied signature count as authority.
4. Observe progress with **both** Runner checkpoint/events and independent Supervisor service health, heartbeat and last progress timestamp. A VALIDATING task with a dead Supervisor is not progress. A nonzero duration since last progress is not itself proof that a task is stuck; compare against the operation's explicit bound and current trusted health.

## Protected recovery runbook

1. **Detect promptly.** The independent monitor should notice stopped workers, missed heartbeats and bounded progress stalls, issue a sanitized alert, and expose STOPPED_OR_UNRESPONSIVE / STALLED_PENDING_DIAGNOSIS with timestamp and last verified task. Verify trusted process health; do **not** tell the owner the run is active solely because the checkpoint still says RUNNING/VALIDATING.
2. **Contain and preserve.** Stop further hazardous write attempts. Pin queue/grant/checkpoint/ledger/event digests, original operation/request identity, complete-task set, verifier results and safe process status. Never restart an uncertain submission to "see what happens," clear a ledger, rewrite a completed task or override frozen outputs.
3. **Gather trusted evidence.** Through a protected least-privilege, **read-only**, credential-redacted diagnostic interface (or owner-controlled terminal until deployed), capture effective approved CLI profile and identity, installed binary/config hashes, return code and redacted stdout/stderr, original Statement/Job ID if known, and exact target/remote object identities. Keep raw secret-bearing material protected.
4. **Reconcile independently.** Check authenticated, appropriately scoped, fully paginated Statement/Query History for the exact time window, remote job/statement state, independently read exact target/UC object and receipt. Record identity, time range, permissions, pagination completeness, delay and visibility uncertainty. Empty results, missing Statement ID or target not-found alone are not "never submitted".
5. **Classify using the [Recovery Decision Matrix](../workflows/agent_operating_contract_v1.md#recovery-decision-matrix).** A: reconcile original, no duplicate write. B: only a distinct bounded recovery if policy already delegates this class, otherwise owner decision. C: maintain UNCERTAIN_REQUIRES_READBACK, owner integrity decision required before fresh write. D: bounded technical correction/resume within deployed authority. E: owner semantic/policy/budget approval or human PR merge.
6. **Execute only after authority.** Any approved separate recovery binds original/new operation identity, request and ledger digests, trust/queue/checkpoint and signed disposition. Install only reviewed/pinned changes in the protected actor. No Agent self-signing, secret disclosure or role escalation; Acquisition performs any authorized missing RAW remediation while Cohort remains RAW-read-only.
7. **Independent postcondition and resume.** Verify exact terminal outcome and independently signed receipt against remote identity/object and original ledger link; prove already-COMPLETE tasks unchanged. Resume the **same** signed queue from its checkpoint, run only impacted verifications, then complete the original Lifecycle acceptance/freeze and applicable human Git merge gate.
8. **Close / measure.** Retain sanitized state, evidence hashes, verifier/alert/heartbeat status, reason and authority, elapsed pause/human minutes/actual retries/resource charges, CI and tested return paths. Unknown values stay null. Do not call the general runtime hardened until stopped-service, hung-service, alert, restart, stale diagnostic and negative replay tests pass.

**Stop conditions:** Conflicting authority, invalid identity/profile, incomplete remote telemetry, inconsistent ledger/receipt/target, missing policy delegation, hard-limit exhaustion, unverified RAW handoff, uncertain effects, failed monitor or a proposed grant/semantic expansion. A stop produces a narrowly scoped owner decision packet; never an inferred new write.

## Routine execution and acceptance

A technical timeout within supported idempotent work can follow an already-authorized bounded retry with immutable checkpoint reuse. Non-idempotent external writes require the independent classification above. Accepted source outputs and freeze receipts must be checked in the live target and against exact source/model/contract identities. Conclude a write task with branch, tests, CI, human P14 review/explicit merge approval (where applicable), and verified remote main SHA. A dry-run, local projection, owner-approved policy proposal or optimistic progress estimate is not an accepted live PASS.
