## Minimal recommended additive M2 scope

Recommend one shared exact `value_decimal` projection capability alongside unchanged original lexical text and source/occurrence/field lineage, scoped to explicitly selected numeric fields. Representation should preserve exact numeric value without a binary-float intermediate or silent rounding. This recommendation does not choose fixed precision/scale, lexical grammar, failure/null encoding or storage layout; those remain later contract questions.

Keep interpretation source-specific: FSDS `value` retains uom, tag/version, adsh, ddate/qtrs and segments/coreg; Treasury retains property QName, source attributes, feed/entry provenance, date, tenor/rate-type context and structural missingness. Do not infer equal units, merge equal-looking fields, scale rates, or reinterpret identifiers/dates as measures. The Treasury parser/integration prerequisite remains separate from the shared numeric capability; this report neither implements it nor approves an XML-to-M1 mapping.

## Historical M1 preservation requirements

Preserve accepted M1 schemas, names, types, exact lexical strings (including empty strings and trailing zeroes), field order, record framing/accounting, multiplicity, dispositions and acceptance/failure behavior. Preserve source identities, frozen memberships/manifests, RAW/member hashes, bindings, technical locators and lineage; do not overwrite frozen version-0 CLEAN outputs or QUERYABLE definitions. New typed output must not replace or mutate those accepted outputs.

Retain existing SQL behavior and exact FIN_001 (two contexts)/FIN_002 (one context with wrong-equity negative control) results and lineage under their pinned source/run/snapshot scope. Historical query-specific Decimal results are regression evidence, not evidence that M1 already exposes the new reusable capability. Later additive validation must establish equivalence of old fields/results and isolate the new projection; backfill/replay is needed only if an explicitly selected historical-support/downstream contract requires it. These are future acceptance obligations, not checks executed here. See [Test A/B1 contract](evaluation_contract.md#test-b1--determine-the-new-cohorts-model-fit) and [additive model guidance](architecture_notes.md).
