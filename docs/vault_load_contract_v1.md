## Deterministic keys and hashdiff

The pure reference is [day6_vault_contract_v1.py](../scripts/day6_vault_contract_v1.py). SHA-256 input starts with `EDP_VAULT_LOAD_V1\0`, then domain and ordered components. Each UTF-8 component has an unsigned four-byte big-endian byte length and exact bytes; `None` is `ffffffff` with no payload. Output is lowercase hex. Store original components and fail closed on hash/component mismatch. No trim, case fold, delimiter joining, implicit type/date coercion or numeric normalization.

Hub keys serialize namespace and exact Business Key components. `L_FACT_SLOT` serializes Filing HK, Concept HK, then fixed-order `(name,state,text)` triples for `ddate,qtrs,uom,coreg,segments`. `state` is `PRESENT`, `NULL`, or `ABSENT`; `PRESENT` plus `""` differs from both. `ABSENT` requires a physically absent source column; NULL requires independently evidenced representation and is never inferred from empty text. Missing parser output for a physically present field blocks promotion. `SOURCE_OCCURRENCE` serializes Source ID, exact member, member SHA, decimal byte offset and length. Assertion child key includes slot HK, occurrence HK and parser version.

`FSDS_NUM_LEXICAL_PAYLOAD` hashdiff serializes field count and every original `(ordinal,name,state,exact lexical text)` in source order. It excludes volatile `run_id` and `load_dts`, and detects payload changes rather than Business Identity. Equal hashdiffs at different occurrence keys stay separate. The typed M2 projection carries its own rule/version/outcome and never changes the original lexical hashdiff.
