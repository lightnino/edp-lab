# Future-day agent operating contract

This contract applies prospectively. It does not rewrite C300/C750/C1500 admissions, historical owner decisions, RAW, or Day 4 evidence. At 0A the owner installs a standing policy in a protected authority. At P5 that authority evaluates each selected run and signs its exact grant automatically; routine P0–P14 execution and resumptions need no new owner infrastructure signature. New business/semantic rules and policy changes still require human approval.

FIN_001/002 and TRY_001–004 exist as scoped SQL, while Lossless/Stability controls and tests are spread across `metadata/evaluations`, `sql/reconciliation` and `tests`. The future path centralizes selection and authority checks without modifying those historical artifacts.

## Queue and checkpoint

`python -m edp_lab.operating.runner QUEUE auto STATE_DIR` requests the policy grant and runs the exact hash-pinned queue. The runner uses Python stdlib, OpenSSL and the optional installed Codex CLI. Its tasks declare IDs, dependencies and typed operations. It writes an atomic checkpoint, JSONL events and a summary. One directory lock per output namespace prevents concurrent mutation. `PLANNED → AUTHORIZED → RUNNING → VALIDATING → COMPLETE` is explicit. A transient timeout becomes `RECOVERABLE_FAILURE`, bounded exponential retry and resume. An interrupted non-idempotent task is isolated for independent disposition; an integrity denial becomes `FAILED_INTEGRITY`. Completed tasks are skipped on resume. External submissions remain `VALIDATING` until a separately signed live readback receipt matches the operation and exact request hash. They are never replayed while waiting. Dry-run completion is `simulation_complete`, never an accepted result.

Every action preserves source references and logs status, retries and measured operation counts. Owner approvals, tool permission requests, steering, manual SHA installations, human minutes, compute and tokens are fields in the checkpoint, with unknown measurements left `null` rather than invented. At the end, compare these measurements with retained Days 3–4 evidence; only measured interventions support the staffing hypothesis.

Routine infrastructure operations continue within the standing policy. New semantic judgments, approved-Universe or policy changes, C3.4 measurements above the applicable 10× gate, and exhausted hard limits retain their respective human-decision or fail-closed boundaries. P14 human PR review and explicit merge approval remain mandatory.

## Validation and economic meaning

The versioned registry `metadata/operating/validation_registry_v1.json` pins existing local Lossless/Stability tests and FIN/Treasury SQL by SHA. Tag applicability selects every matching control and rejects a changed control file; a queue cannot silently omit a selected ID. Local controls execute through pytest for live runs. Databricks SQL controls require separately signed receipts carrying exact control ID, SQL hash and live PASS. New controls require a reviewed registry version, negative tests and changed-source applicability tests. Prior receipts may be reused only when their source/scope/rule pins are unchanged.

`PRESERVED_NOT_MODELED` triggers a separate read-only economic-research task. Its decision packet must inventory original source meaning, grain, units, dates, documented conventions, bounded source-native equations, independently supported cross-source comparisons, alternatives and consequences. Price/yield relationships need fixed cashflows and stated conventions; principal is not price. Unapproved hypotheses stay proposals and do not block independent source-preserving acceptance. Missing properties and undecided semantics are not corrupt records.

## Final Result Freeze and Git

An accepted queue ends with `freeze_verify`. Its live receipt must be separately signed and identify the output plus verified Delta IDs, history, properties, row counts, source lineage, version-pinned QUERYABLE definitions and live readback, with a retained remote receipt SHA. Freeze creation is exclusive and versioned, uses bounded append-only protection where authorized, and never overwrites a historical version. The local gate will not accept the Day 4 Git marker as that receipt. A real Databricks execution and independent receipt signing remain required before operational acceptance.

For a write task, use a feature branch, run relevant tests and Ruff, review diff/evidence, push and open a PR, then wait for required CI and **human PR review and explicit merge approval**. Merge only after that approval and verify the main merge commit. Branch protections and semantic review gates remain in force. Read-only investigations expressly labelled NO GIT CHANGES are exempt.

## Protected recovery decision matrix (R7)

This clarification does not create new recovery delegation or alter 0A/P11 authorization. The independently protected broker/verifier, not the Agent, makes technical classifications and signs only operations explicitly delegated by an owner-installed standing policy. The original ledger, queue, grant, checkpoint, hashes, completed tasks, and frozen results remain unchanged.

| Class | Independent evidence required | Permitted action and escalation |
| --- | --- | --- |
| Existing operation verified | Original request/operation, Statement ID, terminal state, exact UC target, and signed readback agree | Complete the original operation using its verified receipt. Never resubmit. Mismatches block. |
| Pre-submission/no side effects proven | Authenticated, appropriately scoped submission evidence and independent paginated remote readbacks establish no effect, with visibility limits documented | A separately signed, distinct bounded recovery operation is possible **only if an owner-installed 0A policy expressly delegates this exact class and evidence threshold**. Otherwise request owner disposition. |
| Remote state unresolved | Missing/ambiguous Statement ID or response, incomplete history, potential delayed effects, or discrepancies | Preserve original UNCERTAIN_REQUIRES_READBACK ledger and VALIDATING/blocked checkpoint. Read-only reconciliation; no replay. Owner integrity decision is required before fresh non-idempotent submission. |
| Routine transient or configuration failure | Trusted evidence proves there is no uncertain external-write effect; still within installed 0A scope and limits | Bounded automatic repair, polling and same-checkpoint continuation; escalate on exhausted limits or new uncertainty. No per-run infrastructure signature. |
| New semantic/business rule, policy/scope extension, hard integrity/measurement exception, or P14 merge | Separate applicable authority gate | Owner approval or human P14 PR review and explicit merge approval. Never automatically delegate these. |

A missing Statement ID, empty Query History, or absent UC object alone never establishes no effects. Bind any distinct recovery to original/new operation IDs, exact request hash, original ledger hash, grant/queue/checkpoint pins, authenticated remote checks and an auditable signed decision/receipt. No Agent self-signing, root credentials, mutable-worktree authority, uncertain-write replay, Cohort RAW mutation or completed-task re-execution. A least-privilege sanitized read-only decision packet may be exposed by a separately installed protected diagnostic service; this paragraph does not implement it.

For Day 5 C2000, the owner accepted residual uncertainty and signed a distinct recovery operation. That justified human integrity gate is not a general standing delegation. R4 Supervisor liveness/diagnostic implementation remains separate.
