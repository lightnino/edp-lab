# Future-day agent operating contract

This contract applies prospectively. It does not rewrite C300/C750/C1500 admissions, historical owner decisions, RAW, or Day 4 evidence. At 0A the owner installs a standing policy in a protected authority. At P5 that authority evaluates each selected run and signs its exact grant automatically; routine P0–P14 execution and resumptions need no new owner infrastructure signature. New business/semantic rules and policy changes still require human approval.

## Existing-system findings

The historical N750 Step 8 gate pins an owner grant SHA inside `src/edp_lab/ingestion/n750_step8_authorization.py`; installing each new grant required another trusted source edit. Earlier freeze and validation scripts repeat file-pin, membership and result checks for each cohort. FIN_001/002 and TRY_001–004 exist as scoped SQL, while Lossless/Stability controls and tests are spread across `metadata/evaluations`, `sql/reconciliation` and `tests`. CI already runs pytest and Ruff on push/PR. The Day 3 freezes provide pinned version-0 inputs and retained evidence. Day 4 first recorded a Git-only owner override, then PR #50 separately executed and merged a Databricks result view/readback freeze. The future path centralizes selection and authority checks without modifying those historical artifacts.

The historical Day 4 `O_C1500_M2_v1/freeze.json` is a Git-only owner marker. Recheck that evidence and live availability before the next accepted result; do not replay or overwrite its freeze.
2. The owner signs one `EDP_STANDING_POLICY_V1` document using canonical UTF-8 JSON (`sort_keys`, compact separators, one LF). Install the policy, owner/broker/verifier public keys, revocation list, broker signing key, grant store, operation ledger and credentials outside the Agent's writable worktree. Broker and verifier private keys and credentials are available only to separately protected service identities. Set `EDP_OWNER_TRUST_DIR` and `EDP_POLICY_BROKER_SOCKET` to their protected paths. The policy pins the approved Universe, allowed contract versions and hashes, routes, source increment size, operation types, Databricks path/table prefixes, output namespace, Git permissions and hard limits. A verifier-signed prior-cohort receipt carries exact frozen membership and live verification. Policy amendment, revocation and initial protected setup are owner-controlled; no Agent-authored repo file can activate them.
3. At P5 `edp_lab.operating.policy_broker` evaluates the Agent-selected queue and RAW paths/hashes against that policy and Universe, rejects holdouts, overlap, changed contracts and limits, and signs a short-lived exact `EDP_SIGNED_GRANT_V1` for the run. The Runner requests it with `grant=auto`; it never signs. `edp_lab.operating.authority` verifies broker signature, time and revocation on each invocation. The existing write adapters reload the grant, verify exact operation/source/contract scope and reserve operation IDs in a protected ledger. An uncertain submission is blocked from replay until independent readback and disposition. All live Databricks/Git credentials and write invocation must remain behind the protected boundary; an editable in-process check alone does not enforce authority. Existing owner-signed exact grants remain valid for historical reproduction only.

## Queue and checkpoint

`python -m edp_lab.operating.runner QUEUE auto STATE_DIR` requests the policy grant and runs the exact hash-pinned queue. The runner uses Python stdlib, OpenSSL and the optional installed Codex CLI. Its tasks declare IDs, dependencies and typed operations. It writes an atomic checkpoint, JSONL events and a summary. One directory lock per output namespace prevents concurrent mutation. `PLANNED → AUTHORIZED → RUNNING → VALIDATING → COMPLETE` is explicit. A transient timeout becomes `RECOVERABLE_FAILURE`, bounded exponential retry and resume. An interrupted non-idempotent task is isolated for independent disposition; an integrity denial becomes `FAILED_INTEGRITY`. Completed tasks are skipped on resume. External submissions remain `VALIDATING` until a separately signed live readback receipt matches the operation and exact request hash. They are never replayed while waiting. Dry-run completion is `simulation_complete`, never an accepted result.

Every action preserves source references and logs status, retries and measured operation counts. Owner approvals, tool permission requests, steering, manual SHA installations, human minutes, compute and tokens are fields in the checkpoint, with unknown measurements left `null` rather than invented. At the end, compare these measurements with retained Days 3–4 evidence; only measured interventions support the staffing hypothesis.

## Validation and economic meaning

The versioned registry `metadata/operating/validation_registry_v1.json` pins existing local Lossless/Stability tests and FIN/Treasury SQL by SHA. Tag applicability selects every matching control and rejects a changed control file; a queue cannot silently omit a selected ID. Local controls execute through pytest for live runs. Databricks SQL controls require separately signed receipts carrying exact control ID, SQL hash and live PASS. New controls require a reviewed registry version, negative tests and changed-source applicability tests. Prior receipts may be reused only when their source/scope/rule pins are unchanged.

`PRESERVED_NOT_MODELED` triggers a separate read-only economic-research task. Its decision packet must inventory original source meaning, grain, units, dates, documented conventions, bounded source-native equations, independently supported cross-source comparisons, alternatives and consequences. Price/yield relationships need fixed cashflows and stated conventions; principal is not price. Unapproved hypotheses stay proposals and do not block independent source-preserving acceptance. Missing properties and undecided semantics are not corrupt records.

## Final Result Freeze and Git

An accepted queue ends with `freeze_verify`. Its live receipt must be separately signed and identify the output plus verified Delta IDs, history, properties, row counts, source lineage, version-pinned QUERYABLE definitions and live readback, with a retained remote receipt SHA. Freeze creation is exclusive and versioned, uses bounded append-only protection where authorized, and never overwrites a historical version. The local gate will not accept the Day 4 Git marker as that receipt. A real Databricks execution and independent receipt signing remain required before operational acceptance.

For a write task, use a feature branch, run relevant tests and Ruff, review diff/evidence, push and open a PR, wait for required CI/approvals, then merge and verify the main merge commit. Branch protections and semantic review gates remain in force. Read-only investigations expressly labelled NO GIT CHANGES are exempt.
