# Future-day agent operating contract

This contract applies prospectively. It does not rewrite C300/C750/C1500 admissions, historical owner decisions, RAW, or Day 4 evidence. It implements binding rules in `AGENTS.md` using the existing signed-grant runner. **As implemented, the current Runner still requires a separately owner-signed exact queue grant. The Day 5 target is different: 0A provisions a standing, project-scoped infrastructure policy and trusted external issuer once; P5 validates each exact queue automatically without a new human infrastructure signature. This target is NOT yet implemented by editing this document.**

## Start and authority

1. Read current approved scope, source universe, last result freeze and exact physical snapshot references. Establish Git/main, hashes, row counts and prior control outcomes as the baseline. The historical Day 4 `O_C1500_M2_v1/freeze.json` is a Git-only owner marker. PR #50 subsequently merged the [executed Databricks freeze V2](../metadata/freezes/O_C1500_M2_v1/databricks_result_freeze_v2.json), with the [live evaluation](../metadata/evaluations/o_c1500_m2_databricks_freeze_v2.json) and version-pinned queryable view. Recheck that evidence and live availability before the next accepted result; do not replay or overwrite its freeze.
2. The owner signs canonical UTF-8 JSON (`sort_keys`, compact separators, one LF) with Ed25519. `grant.json` contains `grant` and `signature_base64`. Its identity, authority, issue/expiry, revocation ID, exact cohort, source identity-to-SHA pairs, parser/model/rule/queue/statement hashes and versions, operation list, Databricks paths/tables, outputs, Git operations/protected branches and runtime/compute/token/retry/operation limits are explicit. Install `owner_ed25519_public.pem` and `revoked_grants.json` in an owner-controlled directory outside the agent's writable worktree; set `EDP_OWNER_TRUST_DIR` to that absolute directory. The private key never enters this repo or agent workspace. Revoke by appending the grant or revocation ID to the protected JSON list.
3. `edp_lab.operating.authority` verifies signature, time and revocation on each new runner invocation. It verifies each requested operation, scope, source bytes, contract bytes and budget immediately before execution. `edp_lab.operating.boundaries` checks exact SQL/Git requests at the external-write adapter and reserves an operation ID exclusively before submission. An uncertain submission is blocked from replay until independent readback and disposition. Never route a Databricks write or Git mutation around this boundary in an autonomous run. An agent that can edit and run arbitrary code in the same trust domain can bypass an in-process guard; operational enforcement requires the owner to control credentials and invoke the boundary from a separately protected process. This is a deployment condition, not a property proven by local tests.

## Queue and checkpoint

`python -m edp_lab.operating.runner QUEUE GRANT STATE_DIR --dry-run` runs a signed, hash-pinned queue. The Mac runner uses Python stdlib, OpenSSL and the optional installed Codex CLI. Its tasks declare IDs, dependencies and one of `verify_file`, `transient_probe`, `validate_controls`, `codex_task`, `economic_research`, `databricks_write`, `git_write`, `freeze_verify`. It writes an atomic checkpoint, JSONL events and a summary. One directory lock per output namespace prevents concurrent mutation. `PLANNED → AUTHORIZED → RUNNING → VALIDATING → COMPLETE` is explicit. A transient timeout becomes `RECOVERABLE_FAILURE`, bounded exponential retry and resume. An interrupted non-idempotent task becomes `NEEDS_HUMAN_DECISION`; an integrity denial becomes `FAILED_INTEGRITY`. Completed tasks are skipped on resume. External submissions remain `VALIDATING` until a separately signed live readback receipt matches the operation and exact request hash. They are never replayed while waiting. The dry-run probe simulates one transient failure; dry-run completion is `simulation_complete`, never an accepted result.

Every action preserves source references and logs status, retries and measured operation counts. Owner approvals, tool permission requests, steering, manual SHA installations, human minutes, compute and tokens are fields in the checkpoint, with unknown measurements left `null` rather than invented. At the end, compare these measurements with retained Days 3–4 evidence; only measured interventions support the staffing hypothesis.

## Validation and economic meaning

The versioned registry `metadata/operating/validation_registry_v1.json` pins existing local Lossless/Stability tests and FIN/Treasury SQL by SHA. Tag applicability selects every matching control and rejects a changed control file; a queue cannot silently omit a selected ID. Local controls execute through pytest for live runs. Databricks SQL controls require separately signed receipts carrying exact control ID, SQL hash and live PASS. New controls require a reviewed registry version, negative tests and changed-source applicability tests. Prior receipts may be reused only when their source/scope/rule pins are unchanged.

`PRESERVED_NOT_MODELED` triggers a separate read-only economic-research task. Its decision packet must inventory original source meaning, grain, units, dates, documented conventions, bounded source-native equations, independently supported cross-source comparisons, alternatives and consequences. Price/yield relationships need fixed cashflows and stated conventions; principal is not price. Unapproved hypotheses stay proposals and do not block independent source-preserving acceptance. Missing properties and undecided semantics are not corrupt records.

## Final Result Freeze and Git

An accepted queue ends with `freeze_verify`. Its live receipt must be separately signed and identify the output plus verified Delta IDs, history, properties, row counts, source lineage, version-pinned QUERYABLE definitions and live readback, with a retained remote receipt SHA. Freeze creation is exclusive and versioned, uses bounded append-only protection where authorized, and never overwrites a historical version. The local gate will not accept the Day 4 Git marker as that receipt. A real Databricks execution and independent receipt signing remain required before operational acceptance.

For a write task, use a feature branch, run relevant tests and Ruff, review diff/evidence, push and open a PR, wait for required CI/approvals, then merge and verify the main merge commit. Branch protections and semantic review gates remain in force. Read-only investigations expressly labelled NO GIT CHANGES are exempt.
