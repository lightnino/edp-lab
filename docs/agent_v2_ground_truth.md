# Bounded Agent V2 evidence-first ground truth

The [23 labeled cases](../metadata/evaluations/agent_v2/ground_truth_v1.json) are fixed **before Agent V2 implementation or proposal evaluation**. [Inputs](../metadata/evaluations/agent_v2/inputs_v1.json) contain source observations and exact questions without expected labels. Labels: **7 MATCH / 10 NON_MATCH / 6 UNRESOLVED**. Positive labels concern approved numeric representation, bounded lexical/schema aliases or exact nonempty native identifier tokens; none approves a canonical entity relation, business key or semantic mapping.

The host prepared labels from actual evidence; Agent proposal output was not available. This is an evidence-first preregistered engineering set, **not externally human-adjudicated or blinded**. The same development session can see the labels; results must not be advertised as held-out ER accuracy or independent human truth. Labels are never inferred from Agent predictions or altered to improve scores. Later human review, if supplied, is a separate outcome; this initial label version remains intact.

Evidence reuses frozen C300 FSDS field witnesses (SRC000053/54/60), existing GOLD 13F/SRC000001 and FSDS sub/SRC000004 profiling outputs, and the already-versioned five Treasury observations (SRC010451–55). Profiling envelopes were checked with the existing canonical hash function. Profile paths/file hashes and original source/member hashes and locators are in inputs. A few missing native occurrence examples were extracted from the exact hash-verified existing 13F archive and two Nasdaq lines; full member hashes were verified first. This is bounded witness extraction, not new profiling or N750 processing. The 13F bundled README's VALUE description distinguishes historical thousands from later dollar reporting; no currency conversion is performed.

GOLD 13F/FSDS and Nasdaq evidence is supplementary existing evidence, **not a new C1500 admission**. Treasury observations are reused from Step 2 without fresh XML processing. FSDS M1 evidence is reused without RAW or M2 replay. Only partial field observations and references are committed, not RAW files/rows. No full-corpus scan or new profiling framework.

MATCH/NON_MATCH always answers the case's exact question: identical namespaced source token is distinct from same HOLDING/FILING occurrence and from canonical SECURITY identity. Equal CUSIP across two holdings is a token MATCH, an occurrence NON_MATCH, and a canonical-security UNRESOLVED question. Different native listing tokens remain distinct; shared symbol stems do not approve security equality. Business aliases, keys, relationships and interpretation questions remain candidates pending the existing human-review boundary.
